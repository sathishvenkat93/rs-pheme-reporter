## What was built

**M10 — Upload, chat, options, approvals**

- A typed API client over OpenAPI types generated by `make types`, with an XHR upload that reports progress, and upload status polling.
- `src/charts`: one pure ECharts mapping per widget type (all 12). They use theme and status tokens, format percent, ms, bytes and rate, handle empty data and long labels, and draw thresholds and annotations as mark lines. Thumbnails use a compact variant.
- A session provider built on React Query plus SSE. Events invalidate queries, and a pure reducer turns events into the timeline: streamed text, progress lines, plan diffs, the confirm card and edit previews.
- **Chat pane:** drop zone, context box, and chat with quick-reply chips for clarifications.
- **Proposal pane:** option cards (status badge, score breakdown on hover or focus, include toggle, live preview) and approval cards (reason, before/after, all four choices). The "Approve plan" button stays disabled while decisions are open; its tooltip names them.
- Small backend additions for the UI:
  - message history
  - the option toggle
  - dataset ids on the session
  - `events?after=$`
  - decision candidates and before/after
  - `messages.seq` (fixes an ordering bug; details below)

**M11 — Dashboard canvas, library, editing**

- `/d/:id` and `/d/:id/v/:n`: a grid canvas with per-widget loading, empty and error states, a global filter bar, and a read-only view of old versions.
- **Direct manipulation:** drag, resize and inline rename become patch ops sent against your base version. On a conflict (409) the UI refetches and re-applies your change if the widgets it touches are unchanged; otherwise it explains who changed what.
- **Selection:** click, or Shift-click for several. An "Editing:" chip appears in the chat, and the selected ids go with your next message. The agent's edit previews offer Apply and Adjust.
- **Version history drawer:** each version's author, time and note, with diff and restore.
- **Library:** search, domain and tag filters, newest first, and pinned favourites.
- **Upload new data:** refreshes a live dashboard, and shows a proposed field mapping when the file's columns don't fit.
- **PNG export.**

## Deviations from the plan

All of these are logged in `docs/plans/phase-4.md`.

1. **Browser checks are automated.** The "works by hand" items are Playwright specs driving the real app, in headless Chromium.
2. **Assistant replies come from the POST response**; SSE carries progress, deltas, diffs, cards and invalidations.
3. **Single-select global filters**, with values from the top 100 by count.
4. **Pins are stored per browser**, not on the server.
5. **A pending edit survives a reload** as a short card; the before/after rows exist only in the live event.
6. **CI** installs Chromium and runs `make e2e` after `make check`.

**Bugs found and fixed during the phase:**

- Messages written in one request shared a timestamp, so their order (including the LLM's replayed history) was random. Fixed with `messages.seq`.
- Chrome 158's `scrollIntoView` returns a Promise, which crashed an effect. Fixed, and routes now have an error boundary.
- redis-py 8's 5 s socket timeout broke the 15 s SSE blocking read. It now blocks 4 s and sends heartbeats.
- The grid measured its width before mounting, so dashboards overflowed the pane. The grid now mounts once the spec exists.

## Open issues

1. **GitHub push still blocked**, so there's no CI run and no PRs. One push will send all four stacked branches.
2. **Live-LLM run still pending** (no API key). The UI has only been exercised against the offline policy, whose intent parsing is heuristic.
3. **Accessibility:** names, roles and keyboard reach are tested, but there's no automated contrast or screen-reader audit yet. Something to consider for M12.
4. **Layout:** the dashboard grid is fixed at 12 columns, with no responsive breakpoints below 1024 px; the plan only targets ≥ 1024 px.
5. **Toolchain warning:** `react-grid-layout` 2 is new, and `ResizeObserver` and `matchMedia` are untested in old browsers.
